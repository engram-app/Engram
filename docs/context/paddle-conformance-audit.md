# Paddle conformance audit (2026-10-24)

_Last verified: 2026-10-24 against origin/main 735cdeb31_

A read-only check of our Paddle Billing integration against Paddle's docs
(developer.paddle.com) and the Paddle plugin skill checklists. Each row quotes
the doc, cites our code and rates the gap. Rows marked OK already comply.

Triggered by a buyer whose Apple Pay payment sat at `action_required` while our
checkout told them "Payment received"; no subscription was ever created.

Ownership of fixes (2026-10-24):

- Webhook reliability (non-2xx on failure, `occurred_at` ordering, upsert on the
  first event for a subscription): fix/paddle-webhook-reliability.
- Checkout truthfulness (arm "activating" only on `checkout.completed`, a
  closed-mid-payment state, customer-id prefill): fix/paddle-checkout-truthfulness.
- Transactions and invoices ($0 and status filter, paging at 30, history by
  customer id): the trial-invoice-404 PR (#2204).
- Refund and chargeback downgrade, trial copy: the payment-issues PR.
- CSP and Permissions-Policy: the wallet headers PR.
- Trial `do_not_bill` and localized prices (`PricePreview`): filed as issues.
